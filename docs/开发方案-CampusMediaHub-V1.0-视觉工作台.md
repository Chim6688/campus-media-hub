# Campus Media Hub V1.0

# AI 视觉推文生产工作台 · Coding Agent 开发方案

## 1. 项目目标

让小编不离开 Campus Media Hub
工作台，就能完成公众号推文从素材、写稿、配图、视觉设计、排版、检查到审核发布的完整流程。

本方案重点新增：

> **看图选风格 + 模板化视觉图片生产**

核心理念：

> **AI 负责理解与推荐，程序负责稳定设计与渲染，小编负责最终确认。**

最终工作流：

``` text
① 素材 → ② 写稿 → ③ 配图 → ④ 视觉设计 → ⑤ 排版 → ⑥ 检查 → ⑦ 审核 → ⑧ 发布
```

------------------------------------------------------------------------

## 2. 新功能到底要实现什么

小编写完文章后，不需要打开 Photoshop、Canva
等第三方工具，而是在工作台内完成：

``` text
文章内容
+
真实图片
+
参考图
↓
AI 分析视觉风格
↓
8色配色 + stylePreset + 视觉类型建议
↓
选择视觉模板
↓
自动填充文章内容
↓
生成 PNG/JPG
↓
自动保存到当前文章
↓
自动绑定封面或正文图片 Slot
```

目标不是"AI 随机生成一张海报"，而是：

``` text
参考图 / 文章
↓
AI 分析
↓
视觉 DNA
↓
StylePreset
↓
固定结构模板
↓
真实文字 + 真实图片
↓
程序渲染
↓
PNG/JPG
```

这样可以保证中文文字准确、版式稳定、结果可重复、内容可编辑。

# 3. AI 与程序的职责

### AI 负责

-   理解参考图；
-   提取 8 色配色；
-   判断视觉气质；
-   从合法 StylePreset 中选择风格；
-   推荐视觉图片类型；
-   根据文章内容推荐结构；
-   提供视觉设计建议。

### 程序负责

-   结构模板；
-   中文文字；
-   字体、字号、间距；
-   图片裁切；
-   装饰元素；
-   HTML/CSS 或稳定渲染；
-   PNG/JPG 导出；
-   保存；
-   图片 Slot 绑定。

### 小编负责

-   最终选择；
-   修改文字；
-   更换图片；
-   切换风格；
-   确认生成结果。

**不要让视觉模型直接绘制最终中文文字。**

# 9. 第一批 StylePreset

## journal

特点：

-   手账；
-   杂志；
-   轻文艺；
-   大留白；
-   细线；
-   轻装饰。

要求：

> 不指定 StylePreset 时默认 journal，保持现有版本零回归。

## bold

特点：

-   大色块；
-   高对比；
-   强标题；
-   几何结构；
-   年轻；
-   活动感。

## soft

特点：

-   柔和；
-   清新；
-   低对比；
-   圆角；
-   轻量装饰。

# 15. 视觉图片渲染

核心：

``` text
文章数据
+
视觉模板
+
StylePreset
+
8色配色
+
真实图片
+
真实文字
↓
视觉渲染
↓
PNG/JPG
```

优先检查项目是否已有 HTML/CSS → 图片能力。

如果已有，优先复用。

如果没有，再选择稳定方案。

必须保证：

1.  中文文字准确；
2.  中文字体正常；
3.  图片正常；
4.  布局稳定；
5.  输出尺寸固定；
6.  同一数据重复生成结果稳定；
7.  StylePreset 统一控制；
8.  预览与导出尽量一致。

# 32. 风险与降级

## 视觉模型限流

例如 1305：

-   沿用现有错误文案；
-   提示稍后重试；
-   不阻塞手动选风格；
-   不影响文章正常生产。

## AI 选错 StylePreset

允许小编手动切换：

``` text
journal / bold / soft
```

不阻塞主流程。

## AI 返回非法 JSON

处理：

``` text
解析失败
↓
提示识图失败
↓
保留当前主题
```

不能导致页面崩溃。

## 中文字体 / 图片导出问题

必须重点验证：

-   中文字体；
-   字体文件部署；
-   PNG/JPG；
-   图片清晰度；
-   手机显示；
-   长标题。

## 渲染器过度复杂

优先：

``` text
HTML/CSS
文档流
inline-style
固定结构
```

避免为了模仿参考图而过度引入复杂定位和难维护技术。

# 34. Agent 执行规则

**不要一次性实现全部 Phase。**

每个 Phase 独立完成、独立测试、独立验收。

开始编码前：

1.  检查现有代码；
2.  找出相关文件；
3.  说明修改范围；
4.  说明潜在冲突；
5.  提出最小实现方案。

如果发现：

-   当前架构与方案冲突；
-   数据库字段实际情况不同；
-   现有渲染管线不能直接支持；
-   某技术方案风险较高；

**先停下来告诉我，不要擅自大规模重构。**

每个 Phase 完成后：

1.  运行 build；
2.  运行 lint（如果已有）；
3.  运行现有测试；
4.  修复明显问题；
5.  汇报修改文件；
6.  汇报功能；
7.  汇报测试结果；
8.  **暂停等待验收，不自动进入下一 Phase。**

# 37. 最终产品原则

> **简单优先。**

> **先闭环，再高级。**

> **先模板化，再自由化。**

> **先稳定渲染，再增加 AI。**

> **AI 负责理解与推荐，程序负责准确生产。**

> **真实文字由程序渲染，不依赖 AI 在图片中生成中文。**

> **StylePreset 是整篇推文的视觉 DNA。**

> **视觉图片必须直接进入当前文章，而不是让小编下载后再上传。**

> **所有视觉能力最终都服务于"生产一篇完整公众号推文"。**

> **V1.0 的目标不是成为 Photoshop 或
> Canva，而是成为校园小编最快、最简单的公众号推文生产工具。**
