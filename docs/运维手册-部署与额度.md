## 2. Netlify 免费额度现状（2026-09-06）

- 免费计划 300 credits/月，全池共享：生产部署 15/次、带宽 20/GB、请求 2/万次、Functions 计算 10/GB-hour
- **当前余额约 30 credits** ≈ 再部署 2 次，或约 1.5GB 流量（含 AI 功能调用的 Functions 计算）
- 耗尽后果：全站暂停显示 "Site not available"，直到下个账单周期自动重置（恢复 300）；不产生账单，数据不丢
- 邮件提醒阈值：50% / 75% / 100%

## 3. 部署纪律（当前阶段执行）

1. **冻结非必要部署**：每次 push 到 master 成功 = 15 credits
2. 修复类改动**攒批**：多个小修合并成一次部署
3. push 前本地先跑通 `npm run build` + 全量测试，避免浪费（失败部署免费，成功才扣）
4. 部署预览/分支部署免费：改动可先开分支验证再合并

## 4. 触发线与迁移预案

### 触发线（满足任一立即执行 Cloudflare 迁移）
- 线上站点暂停（Site not available）
- 剩余 credits 不足以支撑一次必要修复部署，且当月无法等待重置

### Cloudflare Pages 迁移（免费，约半天工作量）
1. Cloudflare 账号 → Pages → 连接同一 GitHub 仓库
2. 构建配置照搬 netlify.toml：`cd backend/functions && npm install && cd ../../frontend && npm install && npm run build`，产物目录 `frontend/dist`
3. 函数适配：Netlify Functions v2 → Pages Functions（`functions/api/[[path]].js` 路由约定或 `_routes.json`）；两侧同为 Web Request/Response，改动集中在导出方式与路由分发，业务逻辑零改动
4. 环境变量在 Cloudflare 项目设置重配（Supabase / AI Keys，永不入库）
5. 验证 `/api/tasks`、`/api/images`、分享链接后切换
6. 免费额度：静态访问无限、Functions 10 万次/天（每日重置）、部署 500 次/月——内测期不可能触顶

### 国内云 + ICP 备案（正式面向公众运营时才启动）
- 备案法定前提 = 服务器在中国大陆；**Cloudflare 与备案无关**（其"中国网络"是企业版付费功能，且要求先有备案才能开通）
- 主体问题：学生社团非法人，备案需指导老师个人名义或挂靠学校——**先问学校信息化办公室**走校内流程
- 届时迁移目标：腾讯云/阿里云 + 备案 + 域名
