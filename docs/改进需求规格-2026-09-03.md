# 推文工作流站 · 改进需求规格

> **给执行 Agent 的话**:本文档是需求规格,不是代码事实的终点。开工前先通读源码核对"现状"描述,出入以代码为准并在实施计划中说明差异。
> **给用户的用法**:开新会话,让执行 Agent 读本文件(仓库内 `docs/` 下),按"开工流程"执行。

---

## 1. 项目背景

已上线的**公众号推文生产工作流**网站(Netlify 部署,口令 619):

- **使用者**:小编单人全程产文 → 生成分享链接 → 老师(部长/教师)**只读终审**
- **完整流程**:选题登记 → PDF 策划书上传 AI 提取素材 → 一键成稿 → AI 微调(改标题/摘要/选中改写)→ Markdown 双栏排版(手账卡片风)→ 规范检查门禁 → 生成分享链接给老师 → 老师微信给意见 → 打回修改 → 推进已发布 → 归档
- **页面**:列表页(可快速新建)+ 详情页(素材/成稿/排版/检查一页)+ 分享只读页(`/share/:token`)
- **已知痛点(用户访谈结论)**:① 排版模板不灵活(想要的效果做不出来);② 审核意见老师"用嘴说"、容易漏、站内不落档;③ 界面不直观(详情页太满、流程感弱、列表页裸)

## 2. 站点技术现状(仓库内可核实)

**架构**:前端 Vue 3 SPA(`frontend/`)+ **Netlify Functions**(`backend/functions/*.mjs`,同仓)+ **Supabase Postgres 存储**;`netlify.toml` 把 `/api/*` 重写到 functions、`/share/*` 重写到 index.html。

| 项 | 事实 |
|---|---|
| 前端入口 | `frontend/src/App.vue` + `components/`、`utils/`、`api/`;Vite 构建 |
| 后端函数 | `tasks.mjs`(任务 CRUD/流转)、`verify.mjs`(口令)、`ai.mjs`(AI action 分发)、`parse-pdf.mjs`、`check.mjs`(规范检查)、`share.mjs`(只读分享);`lib/` 有 `ai-providers.mjs`、`prompts.mjs`、`rules-engine.mjs`、`auth.mjs`、`supabase.mjs` |
| 存储 | `docs/supabase-schema.sql`:tasks 表,**status = writing / reviewing / published**(旧 typesetting 已并入 writing);已有字段含 `material jsonb`(素材结构化)、`comments jsonb`(默认 `[]`,`[{by,text,at}]`)、`share_token text`(null=未生成);迁移模式 = `alter table ... add column if not exists`(幂等,sql 文件可重复执行) |
| 鉴权 | `verify.mjs` 校验口令;此后请求头带 `X-Access-Code`;`lib/auth.mjs` 处理 |
| 状态机 | writing → reviewing → published;打回实现方式在 `tasks.mjs` 中核实(疑似回 writing 并依赖 comments 记录意见) |
| 编辑器 | 左 Markdown 文本域,右 `innerHTML` 预览;**预览与复制同一份渲染 HTML**;2s 防抖自动保存 |
| 排版引擎 | Markdown → HTML 字符串,**样式全内联**(无外部 class 依赖),皮肤两套(greenPink/greenYellow,`localStorage.themeId`) |
| 复制到公众号 | `navigator.clipboard.write([ClipboardItem({text/html, text/plain})])`,降级 execCommand —— **机制正确,严禁破坏** |
| 组件库 | 双层错位描边标题卡 / 半圆序号胶囊 / 信息卡 / 金句条 / 配图占位框 / 奶油落款卡 |
| AI | 走 `/api/ai` + `/api/parse-pdf`,key 在后端(`.env.local` / `lib/ai-providers.mjs`);**非流式**,长文只有"生成中…" |

## 3. 改进需求(按优先级分批,逐批交付)

> 顺序依据用户访谈:排版收尾、审核来回最痛;界面问题三条全中。每批交付后用户验收再进下一批。

### P0-1 排版:组件参数开放 + 预设灵感库

**目标**:缓解"想要的效果做不出来"。先"能调的让调",不做 AI 生成(留待未来二期)。

**改动**:
1. 把组件的**样式令牌(颜色/圆角/字号/间距/描边粗细)**从渲染代码中抽出为"主题令牌对象",渲染函数读令牌生成内联样式(保持内联策略!)
2. 编辑器加**参数面板**:主题色选择器 + 圆角/字号/间距等可调项,即时反映预览
3. 皮肤 = 预设令牌组合:保留 greenPink/greenYellow,新增若干预设(清新/复古/国潮/简约等方向)
4. 用户自定义组合可保存(存 localStorage 或任务字段,自行权衡)
5. 本期重点是**参数开放,不是堆组件**;少量高频新组件可顺带,勿扩散

**验收**:现有组件能改颜色/圆角/字号/间距且预览即时;预设一键套用、原两套无损;复制到公众号仍全内联格式正常;自定义配置会话内留存。

### P0-2 审核:整改清单式打回

**目标**:老师意见"用嘴说、容易漏、不落档"。**作者侧方案**(老师使用习惯不变):打回 = 站内建整改清单,逐条勾销,清零才可推回审核。

**现状**:意见目前依赖微信,站内 `comments` 字段存在但未结构化使用。

**改动**:
1. 打回动作绑定「整改清单」:支持两种录入——手动逐条录入;粘贴老师微信"语音转文字"→ AI 一键整理为逐条意见(`lib/ai-providers.mjs` 或 `ai.mjs` 需支持新 action,参照现有 prompts 风格)
2. 每条可标记已完成;**存在未完成项时禁止"推回审核"**(置灰 + 提示剩余条数)
3. 清单随任务持久化:扩 `tasks` 表(jsonb 列,如 `review_checklist`,按 `supabase-schema.sql` 幂等迁移模式加列)或扩展 comments 结构;兼容旧任务(无清单不阻塞流转)
4. 意见留档可回看(至少最近一轮),便于复盘老师常挑什么——加分项:分享只读页展示本次清单与勾销进度

**验收**:打回能生成清单(手动/AI 两条路);未清零推回被阻止,清零放行;旧任务不受影响;数据持久化。

### P1-3 详情页:流程步骤条

**目标**:解决"不知道第几步、下一步点哪"。

**改动**:详情页顶部步骤条(选题 → 素材 → 成稿 → 排版 → 审核,对齐状态机与数据完备度);当前步高亮、已完成可点击锚点跳转;数据不满足下一步时提示。**步骤条是引导不是闸门**——不改变现有操作可达性,熟练用户仍可自由点用。

### P1-4 详情页:降密度

**现状**:素材面板 + AI 按钮区 + 双栏编辑器 + 皮肤/组件区 + 门禁操作同屏堆叠。

**改动**:素材面板默认收起(抽屉/折叠,有内容显示摘要态);主区突出「编辑 + 预览」;分区标题明确。**保守**:只做收纳与层级,不重排热区、不砍功能、不动保存/复制主链路。

### P1-5 列表页:分组 + 筛选 + 搜索

**现状**:任务平铺,无筛选。

**改动**:按状态分组(写稿中/审核中/已发布)或状态 Tab + 类型筛选 + 主题关键词搜索(前端过滤即可)。

### P2-6 已发布:一键复用为新任务

**现状**:无复用逻辑(页面文案有"可复用",代码没有)。

**改动**:已发布任务加「复制为新任务」:继承素材 + 排版参数/皮肤,清空成稿,状态重置为 writing(后端 action 或前端 POST 携带字段)。

### P2-7 AI 生成进度提示

**现状**:长文/解析只有"生成中…"。

**改动**:轻量——等待超时(如 8s)后显示等待秒数/步骤文案,避免像卡死。

## 4. 硬约束(红线)

1. **「复制到公众号」机制**:全内联样式 + ClipboardItem(text/html + text/plain)+ execCommand 降级 —— 只许增强,不许推翻
2. **预览 = 复制同一份 HTML** 的架构保持(所见即所得的前提)
3. 口令校验、`X-Access-Code`、分享只读机制不变
4. **旧任务数据兼容**:schema 扩展向后兼容、幂等迁移,不做破坏性迁移
5. 不引入重型 UI 框架,在现有 Vue3 组件体系内扩展
6. **微信兼容性意识**:公众号后台对 flex/部分 position/伪元素支持有限,新皮肤与组件避免依赖;粘贴偏差属微信限制,如实说明即可
7. 口令等敏感配置在 `.env.local`,不入库、不写死进代码

## 5. 开工流程(执行 Agent 必读)

1. 通读核对:前端组件结构、`utils/` 渲染函数、`tasks.mjs` 状态流转与字段、`ai.mjs` action 分发、`prompts.mjs` 提示词风格、schema 迁移模式
2. 出实施计划:按 P0 → P1 → P2 分批,每批含改动文件清单 + 测试方案(含旧任务兼容自测),**交用户确认后再动手**(用户偏好先计划后开工)
3. 每批交付:实现 → 自测 → 给用户演示/测试说明 → 验收后再进下一批
4. 未知信息先问用户,不要猜(部署凭据、口令逻辑、AI provider 选择等)
5. 改动涉及数据库时,把新增 sql 追加到 `docs/supabase-schema.sql`(幂等段)并说明需在 Supabase Dashboard 执行的迁移步骤
